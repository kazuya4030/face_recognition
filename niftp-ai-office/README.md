# NIFTP AI Office（初期版）

CEO が仮想オフィスにいる AI 社員へ仕事を依頼し、進捗確認・成果物の受領・承認／差し戻しを行う**ローカル専用**の Web アプリです。

> 「株式会社NIFTP」は**構想上の名称**です。法人設立状況は未確認で、設立済みとしては扱いません。

- CEO: 植村和也（初期版は CEO 1 名での利用を想定。ログイン機能はありません）
- 表示言語: 日本語
- 2D の俯瞰オフィス（社長室・執務エリア・会議室・資料室）。3D / VR は未対応

## 必要なもの

- Node.js **22.16 以上**（内蔵の `node:sqlite` とそのバックアップ機能を使用。起動時に `ExperimentalWarning` が表示されますが動作に問題はありません）
- 実接続を使う場合のみ: [Claude Code](https://code.claude.com/docs) CLI（`claude`）がインストール・ログイン済みであること
- git（コードの取得用）

## CEO の PC で使う（初回の準備と移行）

このアプリは**使う人の PC の上で**動かします。画面は `http://127.0.0.1:4317/` で、その PC のブラウザからだけ開けます（外部には公開しません）。
開発に使ったクラウド環境の中で動いているアプリは、CEO のブラウザからは開けません。

1. **コードを取得**: `git clone https://github.com/kazuya4030/face_recognition.git` → `cd face_recognition` → `git checkout ccr-8e78d574-9ycuze` → `cd niftp-ai-office`
2. **依存関係**: `npm install`、画面のビルド: `npm run build`
3. **Claude Code のログイン**（実接続を使う場合）: ターミナルで `claude` を起動してログイン。
   - Claude のアカウント（サブスクリプション）でログインした場合、使用量はそのアカウントの利用枠から差し引かれます。API キー（`ANTHROPIC_API_KEY`）を使う場合は従量課金です。どちらを使うかは CEO が決めてください。アプリはどちらで動いているかを「業務状況」画面に表示します。
   - アプリの費用表示は Claude Code が報告する**推定値**で、実際の請求額ではありません。
4. **環境の確認**: `npm run doctor`（Node.js・Claude Code・ログイン・画面のビルド・データとバックアップの保存先を確認）
5. **既存データの移行**（受け取ったバックアップがある場合）: `npm run backup:verify -- <バックアップのファイル>` で中身を確認し、`npm run restore -- <バックアップのファイル>` で `data/` に復元
6. **起動**: `npm start` → ブラウザで `http://127.0.0.1:4317/` を開く
7. **最初に**: 「業務状況」でバックアップを作成し、ダウンロードして PC 以外の場所にも保存

配布物（リポジトリ・バックアップ）には、認証情報・API キー・セッショントークンを含めていません。`.env` やバックアップのファイルはリポジトリに含めないでください（`.gitignore` 済み。リポジトリは公開設定です）。

## 起動方法

```bash
cd niftp-ai-office
npm install
npm run build
npm start
# → http://127.0.0.1:4317/ をブラウザで開く
```

開発時（画面のホットリロードあり）:

```bash
npm run dev
# → http://127.0.0.1:5173/ （API は 4317 へ中継）
```

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `4317` | サーバーのポート |
| `HOST` | `127.0.0.1` | `127.0.0.1` / `localhost` / `::1` 以外は起動を拒否します |
| `NIFTP_DATA_DIR` | `./data` | DB・作業ディレクトリ・成果物・資料の保存先（git 管理外） |
| `NIFTP_BACKUP_DIR` | `./backups` | バックアップの保存先（git 管理外。データとは別の場所） |
| `NIFTP_CLAUDE_BIN` | `claude` | Claude Code CLI のパス |
| `NIFTP_DEMO_STEP_MS` | `1200` | デモ実行の 1 手順あたりの待ち時間 |
| `NIFTP_CLAUDE_ENV_PASSTHROUGH` | なし | Claude Code に追加で渡す環境変数名（カンマ区切り）。通常は不要 |

停止は `Ctrl+C`。実行中の工程は「中断」として記録され、次回起動時に自動で再実行はされません。

## 毎日の使い方（CEO）

| やりたいこと | 画面 |
|---|---|
| 対応が必要なことを見る（質問への回答・作業計画の承認・成果物の承認／差し戻し・失敗と保留への対応） | **受信箱**（上部の件数バッジ） |
| 仕事を頼む（テンプレート・資料の添付・承認済み成果物の参照） | **仕事の依頼** |
| 実行中・実行待ちの案件、順番の変更、全体の開始／停止 | **待ち行列** |
| 進行中・止まっている・完了した仕事、次に判断すること、利用状況と上限、バックアップ | **業務状況** |
| 会社の方針・仮説・未決事項、承認済み成果物、案件で受けた指摘 | **会社の記憶** |
| 承認した成果物を読む・ダウンロードする・次の依頼に渡す | **資料・成果物**（「承認した版だけを表示」） |
| 社員の担当・上限・会社の基本情報 | **設定** |

### 仕事の流れ（継続運用）

```
CEO: 目的・資料・希望する成果を入力（テンプレートも使える）→ 待ち行列へ
ハル: 作業計画（必要な工程・担当・入力と提出物・完了条件・不足情報・CEO判断が要る箇所）
  └ 結論や範囲を左右する不足 → 受信箱に「質問」→ 回答すると作業計画を回答つきでやり直す
  └ 軽微な不足 → 仮定を明示して進める
CEO: 受信箱で作業計画と工程ごとの指示を確認・修正して承認（または作り直しを依頼）
ミナ: 調査（Web 必須／資料の整理のみ を選べる）→ ソラ: 成果物作成 → リツ: 別実行でレビュー（不合格は1回まで自動修正）
CEO: 受信箱で版を確認して承認、またはコメント付きで差し戻し → 「続きから開始」で次の版
```

- 同時に実行するのは 1 件です。ある案件が CEO の回答待ち・計画確認待ちで止まっていても、次の実行待ちの案件に進みます。
- **全体停止**（待ち行列を停止）: 新しい案件・工程を始めません。実行中の工程は最後まで実行し、次の工程の前で待機します。
- **工程を止める**: 実行中の工程を中断して案件を保留にします。再開するとその工程をやり直します（成功済みの工程は再実行しません）。**キャンセル**は案件そのものを取り消します。
- 回答・承認・開始を二度送っても、二重には実行されません（状態を確認して 2 回目は拒否します）。
- 資料（.txt / .md / .csv、1件 1MB・10件まで。Shift_JIS は UTF-8 に変換）は開始時に固定され、全工程に渡されます。PDF・Word・Excel は未対応です。資料の中の指示は、会社方針や権限の変更としては扱いません。
- 承認済みの成果物は、案件・成果物・版・承認を記録して次の案件の参照資料にできます。承認は「その版を受け取った」ことで、会社方針として採用したことではありません。
- 会社の記憶（方針・仮説・未決事項）は版つきで、案件の開始時に ID と版を固定します。途中で編集しても実行中の案件の入力は変わりません。
- 差し戻し・回答などの CEO の指摘はその案件だけに使われます。全案件に適用するには「会社の記憶」で **会社共通の方針に登録** を押します（自動では登録しません）。
- 作業計画を承認しても、外部送信・公開・契約・支払いの権限は増えません。
- 業務テンプレート（調査・比較／顧客ヒアリングからの提案準備／資料レビュー）は、工程の有無・工程ごとの指示・完了条件の初期値です。依頼時に自由に編集できます。

## 画面ごとの説明

1. **オフィス（NIFTP本社）**: 斜め上から見下ろす 2.5D の本社です。入口から見える黒い壁の NIFTP ロゴ（エントランス）、大型モニターが並ぶ共同デスク、ガラス張りのプロジェクトルーム、ソファと低いテーブルのラウンジ、コーヒーカウンターと資料棚、街並みの見える大きな窓があります。CEO もチームと同じ共同デスクで働いています（専用の社長机はありません）。
   - AI 社員は仮の名前（ハル／ミナ／ソラ／リツ）を持ち、髪型・スマートカジュアルの服装（シャツ・ニット・パーカー・Tシャツ）・小物で見分けられます。名前・作業指示は設定で変更でき、設定の「色」は机のマグカップなど小物の差し色に使われます。
   - **画角**: 初期表示は共同デスクと壁面ロゴを中心にした寄りの構図です。ドラッグで移動、ホイール（スマートフォンは2本指）で拡大・縮小、左下のボタンで「＋／－」「オフィス全体」「デスク中心」を切り替えられます。ドラッグした後のクリックでは社員を選びません。スマートフォンの縦スワイプはページのスクロールに使われます。
   - 普段は小さな名札と状態（記号＋文字。例: 「作業中 2/3」「デモ実行 1/2」「! 確認待ち」「× エラー」）だけを表示します。
   - **社員を選ぶ**と、その社員とデスクを控えめに強調して寄り（パネルに隠れない位置）、詳細パネルが開きます。内容は名前・役割・得意な仕事、状態と最終更新時刻、取り組んでいる案件と工程、直近の成果物、CEOへの確認事項。エラーのときは理由と次の対応も表示します。社員の様子の説明は実際の状態から作る短い文だけで、発言は作りません。
   - パネルの操作は実際に使えるものだけです：「仕事を依頼する」（担当が選ばれた状態で依頼フォームを開く）、「案件を見る」、「成果を見る」（実在する成果物）、「確認に答える」（該当の承認・差し戻しへ）。閉じると元の画角に戻ります。
   - 状態は「待機中／作業中／確認待ち／完了／エラー」。まばたき・呼吸は装飾ですが、画面の光や作業中の動き・進捗（例: 2/3）は**実際に実行中のときだけ**表示されます。
   - 作業開始・引き継ぎ（レビュー依頼）・完了・承認待ち・成果物の保存は、**実際に記録された出来事**が届いたときだけ、短い吹き出しや書類の受け渡しで表します。社員の発言や成果を作り出して表示することはありません。見逃しても「出来事」パネルと案件の作業履歴で同じ内容を確認できます。
   - CEO の席に承認待ちの通知、資料棚に新着成果物の通知が出ます（クリックで承認・成果物へ）。新着はこのブラウザで未読のものです。
   - クリック先: CEO→承認待ち、資料棚→成果物、プロジェクトルーム→仕事の依頼、ホワイトボード→案件ボード、プロジェクトボード（コーヒーカウンターの上）→実際の案件と成果物の一覧（案件がなければ「最初のプロジェクトを始める」）、ロゴの壁・扉→会社情報。
   - 仕事の進み具合の表示：作業開始で担当のモニターが点き作業中表示に、レビュー移行や成果物の保存・承認待ち・エラーは左上に短い通知（引き継ぎ元→先）、成果物は資料棚に新着、承認待ちはCEOの席と承認一覧に表示します。画面を開いた後に新しく記録された出来事だけを演出し、再読み込みや再取得で繰り返しません。演出は表示側だけで、処理を遅らせません。
   - オフィスの中で探さなくても、「一覧」（PC）または下部タブ（スマートフォン）の社員・案件一覧から同じ操作ができます。
   - 上部には稼働モード（デモ／実接続）、作業中・承認待ちの件数、実行中の案件の一時停止・キャンセルだけを表示します。
   - 窓の外の明るさは、閲覧している端末の現在時刻（昼・夕方・夜）に合わせています（表示確認用に URL へ `?sky=day` などを付けると固定できます）。
   - 「動きを減らす」（上部ボタン、または設定 → 表示）で演出を止められます。OS のアニメーションを減らす設定（prefers-reduced-motion）にも従います。
   - スマートフォンでは寄りの構図から始まり、下部タブで「オフィス／社員／案件」を切り替えられます。社員の詳細は下から開くパネルで表示し、選んだ社員はパネルの上に見える位置へ移ります。
2. **仕事の依頼**: タイトル・目的・依頼内容・完了条件・担当社員を入力し、「登録のみ」または「登録して開始」。
   進め方（業務責任者AIの作業計画／調査・企画AIの調査／品質確認AIのレビュー）と実行方式（デモ／Claude Code）を選べます。
3. **案件ボード**: 未着手・作業中・確認待ち・完了・エラーの 5 列。カードから案件詳細へ。
   - 上部の「表示」で、すべて／実案件（Claude Code）／デモ案件を切り替えられます。
   - 案件詳細: 開始（差し戻し・失敗の後は「続きから開始」と「最初からやり直す」）・一時停止・再開（回答・指示を添えられる）・キャンセル。押せない操作は無効表示になり、理由を確認できます。
   - 実行履歴（工程・版・担当・結果・レビュー判定・開始と所要時間・ターン数・費用、各工程の入力ファイル・出力ファイル・終了日時・モデル・トークン数）、作業履歴（実行した操作・結果・根拠・確認事項）、提出物（版ごとの保存版）、承認記録（どの版を承認・差し戻したか）。
4. **承認**: AI 社員からの確認依頼に、承認／差し戻し（コメント必須）を返します。確認依頼には**成果物の版**（第N版）、レビューの判定（合格／不合格／判定不明）、確認対象の保存版ファイル（ID と SHA-256）が付きます。判断はその版にだけ有効で、修正版には引き継ぎません。
   差し戻すと案件は「未着手」に戻り、コメントは `inputs/ceo_feedback.md` と依頼書（`brief.md`）に追記されます。修正の開始は CEO が「続きから開始（成果物作成から）」で行います（作業計画・調査結果は引き継ぎ）。
5. **資料・成果物**: 案件ごとの成果物一覧と内容表示。成果物は AI が作業ディレクトリの `outputs/` に実際に作成したファイルだけを、記録時点の内容で保存しています。ファイルがない場合はリンクを表示しません。
6. **設定**: 会社情報（確定事項・仮説・未決定／未確認を分けて編集）、社員の名前・役割・説明・担当指示・提出形式・人間に戻す条件・参照できる情報・使えるツール、既定の実行方式、各種上限。

### 仕事の流れ

```
CEOが依頼 → [ハル: 作業計画] → [ミナ: 調査] → [担当: 成果物作成 第N版] → [リツ: 別実行でレビュー]
                                                    ↑                         │不合格（自動修正は既定1回まで）
                                                    └─────────────────────────┘
          → CEO確認待ち → 承認して完了（第N版）
                        → 差し戻し → 続きから開始 → 成果物作成 第N+1版 → レビュー → CEO確認待ち
```

| 社員 | 担当 | 出力ファイル | 参照できる情報（既定） |
|---|---|---|---|
| ハル（業務責任者） | 依頼を工程に分け、担当・必要な入力・完了条件を決める | `outputs/plan.md` | 依頼書・会社情報・CEOのコメント |
| ミナ（調査・企画） | 情報を集め、根拠と仮説を分けて整理する（Web 検索） | `outputs/research.md` | ＋作業計画 |
| ソラ（制作・開発） | 調査結果を使い、指定された成果物を作る | `outputs/deliverables/`・`outputs/report.md` | ＋調査結果・前の版へのレビュー |
| リツ（品質確認） | 成果物を依頼条件と原資料に照らして確認し、問題点と合否を出す | `outputs/review.md` | 依頼書・会社情報・作業計画・調査結果・提出物 |

- 工程の順番・担当・入力ファイル・出力ファイルの受け渡しは**プログラムが決めます**（AI に段取りを任せたり、受け渡しのために AI を呼んだりしません）。各工程の指示には「【入力ファイル】」「【出力ファイル】」の一覧が入り、実行履歴に入力・出力・開始と終了日時・失敗理由が残ります。
- 各社員の担当指示・提出形式・人間に戻す条件・参照できる情報・使えるツールは設定で編集できます（参照できる情報は入力として渡すファイルの範囲で、作業ディレクトリ内のアクセス制限ではありません）。
- 必須の出力ファイルを作らなかった工程は、AI が成功と報告しても**失敗**として扱います。担当外のファイルを変更した場合は確認事項に残ります。
- レビュー（リツ）は成果物作成とは**別の実行**ですが、同じモデルを使う場合は独立した検証とは扱わず、確認事項にその旨を表示します。
- レビューが不合格のときは、指摘ファイル（`inputs/review_feedback_r<版>.md`、レビュー結果からプログラムが作成）を入力にして成果物作成からやり直します（既定 1 回）。再び不合格なら、不合格のまま CEO 確認待ちになります。修正前の成果物とレビューは保存版として残ります。
- 「人間に戻す条件」に該当した確認事項（重大）が出たら、次の工程の前で停止します。CEO は回答・指示を添えて「再開」できます。
- 調査で Web 検索が 1 件もできなかった場合は、**調査済みとして扱わず調査工程を保留**（一時停止）します。ページ本文を取得できなかった場合は、出典が検索結果の題名・抜粋による確認であることを確認事項に残します。
- 会社情報（`reference/company.md`）は確定事項・仮説・未決定（未確認）を分けて渡し、入力されていない実績・顧客・売上は存在しないものとして扱うよう指示します。

各工程は 1 件ずつ順番に実行されます（同時実行数 1）。後から依頼した案件は「実行待ち」になります。

### 一時停止の扱い

- 実行待ち: すぐに保留になります。
- デモ実行中: 手順の区切りで停止し、再開すると続きから実行します。
- Claude Code 実行中: 実行中のプロセスを途中で止めて再開することはできないため、**次の工程の前**で停止します。最終工程の実行中は一時停止ボタンが無効になります（キャンセルは可能）。

## 実行方式

### デモ実行（既定）

定型の手順と定型テキストで、一連の流れを確認するためのものです。**実際の AI による調査・制作ではありません。**
画面上部に「デモモード」と表示され、デモの成果物・実行には「デモ」バッジが付き、ファイル先頭にも「【デモ出力】」と明記されます。
依頼画面で「途中でエラーになる」「タイムアウトする」シナリオを選ぶと、エラー表示を確認できます。

### Claude Code（実接続）

導入済みの Claude Code CLI を非対話モードで起動し、実際に作業させます。設定画面で検出状況（バージョン）を確認できます。

**接続方法**

1. Claude Code をインストールし、ターミナルで `claude` を一度起動してログインしておく（または `ANTHROPIC_API_KEY` を設定）。
2. アプリを起動し、「設定」で Claude Code が「利用可」になっていることを確認（「検出を再確認」ボタンあり）。
3. 依頼画面で実行方式に「Claude Code」を選ぶ。既定にする場合は「設定 → 新しい依頼の既定の実行方式」。

**起動内容**（`server/src/runner/claudeAdapter.ts`）

```
claude -p --output-format stream-json --verbose
       --tools <社員ごとの許可ツール（Bash なし）>
       --permission-mode acceptEdits --permission-prompts none
       --max-turns <上限> --max-budget-usd <上限>
       --no-session-persistence --strict-mcp-config --disallowedTools "mcp__*"
       --append-system-prompt <会社共通ルール + 社員の作業指示>
       --json-schema <報告形式> [--model <モデル>] [--allowedTools WebSearch,WebFetch]
```

- 作業ディレクトリ: `data/workspaces/job-<番号>/`（案件ごとに分離）。依頼内容は `brief.md` と標準入力で渡し、コマンドラインに埋め込みません（シェルも使いません）。
- 権限: 作業ディレクトリ内のファイル編集のみ自動許可。それ以外の操作は確認できる人がいないため自動的に拒否され、拒否は作業履歴に「権限拒否」として残ります。権限確認を無効化するオプションは使いません。
- Web: 調査・企画AI は既定で WebSearch / WebFetch、品質確認AI は WebSearch（いずれも読み取りのみ）を使えます。設定画面で外せます。
  WebFetch（ページ本文の取得）は、実行環境のネットワーク設定で外部サイトへの接続が許可されている必要があります。Claude Code on the web などのクラウド環境では、環境のネットワークアクセス設定で許可する範囲を広げてください（[Network access](https://code.claude.com/docs/en/cloud-environments#network-access)）。許可されていない場合も検索（WebSearch）は使えることがあり、その場合の出典は「検索結果のみ」として扱われます。
- 環境変数: 許可リスト方式で渡します（`PATH`・`HOME`・プロキシ・Claude Code の認証関連など）。GitHub トークンやクラウドの資格情報は渡しません（Bedrock / Vertex 利用時のみ該当する資格情報を渡します）。
- 記録: ツール操作（例: 「ファイルを書く: outputs/report.md」）、結果の要約、根拠、確認事項、権限拒否、費用（`total_cost_usd`）、ターン数、モデル名（起動時の `init`）、トークン数（`usage`。なければ「未取得」）、レビュー判定・Web の利用状況（`--json-schema` の報告と、実際の WebSearch / WebFetch の成否）。AI の内部思考は記録しません。
- 費用: Claude Code が報告する**推定値**です（サブスクリプション利用時は実際の請求額とは異なります）。報告がない場合は「未取得」と表示し、推測値は表示しません。

仕様の根拠: Claude Code v2.1.312 の `claude --help` と公式ドキュメント（[Run Claude Code programmatically](https://code.claude.com/docs/en/headless)、[CLI reference](https://code.claude.com/docs/en/cli-reference)）。

## 安全上の制限・仕組み

- サーバーはローカル（127.0.0.1）でのみ待ち受け、`Host` ヘッダーを検査します。変更系 API は独自ヘッダー必須（他サイトからの送信を防止）。
- メール送信・外部公開・支払い・ファイル削除などの外部に影響する処理は行いません（必要な場合は AI が確認事項として挙げます）。
- 上限（設定画面で変更可、範囲制限あり）: 1 工程あたりのターン数（既定 30）・費用（1.0 USD）・時間（900 秒）、1 案件の費用（5 USD。報告された推定値の合計で判定し、各工程の `--max-budget-usd` は残り予算以下に抑える）、1 回の実行で起動する工程数（8）、レビュー不合格時の自動修正（1 回）、1 日の実接続の工程数（20）、1 日の費用（10 USD）・1 か月の費用（50 USD。いずれも報告された推定値の合計）、1 回の実行で工程に使える時間の合計（3600 秒）、1 案件の実行回数（5）、デモの制限時間（20 秒）、同時実行 1 件。上限に達した場合は工程を開始せず、理由を受信箱と案件に記録します（「続きから開始」で、止まった工程から再開できます）。
- 費用は推定値で判定するため、上限ちょうどで止まることは保証できません（工程の途中で少し超えることがあります）。費用を取得できなかった工程があると 0 円とはみなさず「未取得」と数え、次の工程の前で停止します（CEO が「再開」すると続行）。ターン数・時間・工程数の上限は費用が分からなくても効きます。
- 失敗・タイムアウト・キャンセル・中断はそのまま記録し、完了扱いにしません。
- 再起動時: 実行中だった案件は「エラー（中断）」、実行待ちだった案件は「一時停止」になり、自動では再実行しません（同じ工程を重複して実行しません）。

## バックアップと復元

- **作成**: 「業務状況」→「今すぐバックアップを作成」、またはターミナルで `npm run backup`（サーバー稼働中でも可。SQLite のバックアップ機能で整合した DB を取り、作業ファイル・成果物の保存版・資料と一緒に `backups/niftp-backup-<日時>.tar.gz` にまとめます。各ファイルの SHA-256 を `manifest.json` に記録）
- **保管**: 画面の「ダウンロード」で取り出し、PC 以外の場所（外付けドライブ・クラウドストレージ等）にも保存してください。同じ PC の中だけでは、PC の故障に備えられません。
- **確認**: `npm run backup:verify -- <ファイル>`（全ファイルの SHA-256 と DB の件数を照合）
- **復元**（サーバーを止めてから）:
  - 別の場所で確かめる: `npm run restore -- <ファイル> --data-dir ./data-restored` → `NIFTP_DATA_DIR=./data-restored PORT=4318 npm start`
  - 今のデータと入れ替える: `npm run restore -- <ファイル> --force`（今のデータは削除せず `data.before-restore-<日時>` に退避）
- 画面からの復元はできません（実行中のデータを上書きしないため）。

## 運用：起動・実行・停止・復旧

- **起動**: `npm run build && npm start`（http://127.0.0.1:4317/）。起動時に前回の状態を復旧します（下記）。
- **実行**: 依頼画面で「登録して開始」、または案件詳細の「開始」。実行は**サーバーのプロセスの中**で行われるため、ブラウザを閉じても続きます。画面を開き直すと記録から状態を表示します。
- **実行される条件**: サーバーのプロセスが動いている間だけ実行されます。**PC がスリープ・休止している間や、サーバーを止めている間は実行されません**（予約実行や常駐の仕組みはありません）。
- **停止（案件）**: 「一時停止」は工程の区切りで止まります（Claude Code の実行途中では止められません）。「キャンセル」は実行中の Claude Code に停止信号（SIGINT→SIGTERM→SIGKILL）を送り、キャンセルとして記録します。
- **停止（アプリ）**: `Ctrl+C`。実行中の工程は「中断」として記録されます。
- **復旧**: 再起動すると、実行中だった案件は「エラー（中断）」になります。実行待ちの案件は待ち行列に残り、待ち行列が**停止状態**で始まるので、CEO が「待ち行列を開始」するまで実行しません。案件詳細で理由を確認し、「続きから開始（中断した工程から）」「最初からやり直す」「再開」のいずれかを CEO が選びます。前の工程の出力は作業ディレクトリに残っているため、続きから開始すれば作業計画・調査をやり直さずに済みます。
- **保留（一時停止）からの再開**: Web 調査ができずに保留した場合は接続を直してから「再開」、人間に戻す条件で止まった場合は回答・指示を入力して「再開」します。
- **デモと実案件**: デモ実行の案件・成果物には「デモ」バッジが付き、案件ボードで実案件とデモ案件を分けて表示できます。デモ実行は費用が発生せず、実際の調査・制作は行いません。

## 現在の制限

- 利用者は CEO 1 名のみ。ログイン・権限管理はありません（ローカル専用のため）。
- 同時実行数は 1。複数エージェントの並列実行は未対応（`maxConcurrentRuns` で拡張できる構造）。
- 社員の追加・削除は未対応（既存 4 名の編集のみ）。
- Claude Code の工程途中での一時停止・再開は未対応（工程の区切りでのみ停止）。
- 小サイズ用の正式なシンボル素材がないため、ブラウザのタブのアイコンはロゴを切り抜かず、インクブラックの無地にしています。
- 共同デスクの席は社員 5 名＋CEO 分です。
- オフィスの家具配置と社員の見た目はコード内のデータ（`client/src/office/layout.ts`・`appearance.ts`）で定義しています。画面からの模様替え・着せ替えは未対応です。
- 社員を増やす機能自体は未対応です。
- 成果物のプレビューはテキスト形式のみ（Markdown は整形せずそのまま表示）。それ以外はダウンロード。
- Windows での Claude Code 起動は未確認（`claude.cmd` の扱いが必要になる可能性があります）。
- 3D / VR、外部公開、クラウド同期は対象外。
- 実行はサーバーのプロセスが動いている間だけです。PC のスリープ中・停止中は進みません。予約実行・常時稼働・外出先からのアクセスは未対応です。
- 添付資料は TXT・Markdown・CSV のみ（PDF・Word・Excel・画像は未対応）。成果物の PDF・スライド出力は未対応です。
- 過去の成果物は一覧から選ぶ方式です（全文検索・自動検索はありません）。
- 復元はコマンドで行います（画面からはできません）。自動の定期バックアップはありません。
